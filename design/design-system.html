DESIGN
PRINCIPLES

基於 Persona 3 Reload UI 語言萃取的設計原則與 Design Token 規範。本文件為開發作品集網站的視覺基礎。

01 Design Principles 設計原則
色彩
DUAL-TONE TENSION
雙極張力

深海軍藍（#080C22）與電光藍（#0F3BB8）以對角線銳利分割，比例約 45:55，無漸層過渡。兩色不調和，製造動態張力——深色代表沉穩身份，亮色代表積極選項。青色（#00C8FF）為唯一第三色，專屬互動狀態。

字體
TYPE AS STRUCTURE
文字即架構

標題字（超粗斜體壓縮體）不只傳達資訊，而是版面的視覺骨架。「JADE」字高佔左側版面 40%，「WORKS」跨越頁面頂部 30%。字型永遠是 Italic + 800–900 weight + Condensed，三者缺一不可。

造型
ZERO SOFTNESS
銳角拒絕柔化

系統中所有元件使用 0px border-radius。選取 highlight bar、卡片縮圖、分類標籤、按鈕——全部直角。唯一例外為濾鏡 tab 的 2px 微圓角。圓角在此設計語言中等於妥協，與整體強硬個性相悖。

佈局
GAME-UI DENSITY
遊戲級資訊密度

間距基於 8px 網格，整體偏密集——選單項目間距 16–20px，版面邊距 32–48px。刻意不留過多呼吸感，製造「資訊豐富」的遊戲 UI 滿足感。空白是刻意節省的資源，而非預設的美學選擇。

互動
ONE ACCENT ONLY
唯一焦點色

整個系統只有一個互動/選中顏色：青色 #00C8FF。它的出現即意味著「當前選中/活躍狀態」，從不用於裝飾。其他所有文字皆為純白或半透明白。青色的稀缺性使它的每次出現都有意義。

層次
OPACITY HIERARCHY
透明度決定層次

層次感透過白色透明度建立，而非不同顏色。主文字 100%、次要文字 65%、輔助文字 40%、幽靈背景文字（大數字 01-06、PORTFOLIO 字樣）僅 8–12%。背景大字製造景深，從不搶奪視覺焦點。

情境
TEMPORAL ANCHOR
時間作為 UI

右上角即時顯示日期、星期、時段（10/29 THU 午後·AFTERNOON），直接借鑑 P3R 的日曆系統。它強調「當下性」與個人化感，同時是版面右上角不可或缺的視覺錨點，讓靜態頁面具備動態感。

⚠ Anti-AI Slop Rules — 必須避免
  • 禁止使用漸層背景（兩色之間無 gradient，只有銳利分割線）
  • 禁止半透明卡片背景（backdrop-filter / frosted glass 效果）
  • 禁止大於 2px 的圓角（特別是 rounded-lg、rounded-xl 完全禁止）
  • 禁止多種強調色（只允許一種：青色 #00C8FF）
  • 禁止過度使用卡片容器（卡片包卡片、陰影堆疊）
  • 禁止居中排版的英雄區（JADE 名稱靠左對齊，非居中）

07 Design Token 繼承架構

遵循 Google Material Design 3 三層繼承格式。每個設計決策只定義一次——修改 Ref 層數值，System 與 Component 自動繼承更新。

01 · Reference
原始值層。定義所有可用的原始設計資源——調色盤、字型名稱、像素數值。不帶語意，只是純粹的值。
--ref-palette-cyan80: #00C8FF
--ref-spacing-8: 8px
--ref-duration-80: 80ms
→
02 · System
語意角色層。將原始值賦予設計意圖——「這是主要強調色」而非「這是 #00C8FF」。換主題只改這層。
--sys-color-primary: var(--ref-palette-cyan80)
--sys-gap-md: var(--ref-spacing-16)
--sys-motion-snap: 80ms steps(1)
→
03 · Component
元件專屬層。每個 UI 元件明確宣告使用哪個 sys token，永不直接引用 ref 層原始值。
--comp-nav-active-bg: var(--sys-color-primary)
--comp-card-gap: var(--sys-gap-md)
--comp-cursor-dur: var(--sys-motion-snap)

08 Component 開發方法 & Primary Button

Token 命名規則 + Primary Button 作為完整範本。未來每個新元件皆依此方法建立。

Token 命名規則
--comp - {component} - {slot} [- {variant} optional ][- {state} optional ]
--comp固定前綴，宣告這是 Component Token 層
{component}元件識別碼，kebab-case。如 btn-primary、nav-item、work-card
{slot}視覺插槽，描述元件哪個部位的哪個屬性。如 bg、label-color、shape、padding-x、height
{variant}可選，元件變體。如 outlined、ghost、secondary。無變體時省略
{state}可選，互動狀態後綴。hover / pressed / focus / disabled / active。預設態省略
規則：Component Token 只能引用 sys 層，永遠不直接使用 ref 原始值。sys 層改一次，所有引用該 sys token 的元件自動更新。

新元件開發 Checklist

每個新元件進行 Token 定義時，依序完成以下四步驟。

1
確認 sys 層是否有對應值
先查 Section 07 的 System Token 表。若語意角色已存在（如 sys.color.primary），直接引用，不建立新的 ref token。
✓ 已有 sys.gap.md → 直接用，不另建 --ref-spacing-16-for-button
2
建立 comp token，引用 sys（不用 ref）
格式嚴格遵守：--comp-{component}-{slot}[-{state}]。slot 名稱用 kebab-case，語意清晰（bg、label-color、shape、height）。
✓ --comp-tag-bg: var(--sys-color-primary)   ✗ --comp-tag-bg: #00C8FF
3
定義所有互動狀態
預設態省略 state 後綴。其餘狀態依需求加後綴：-hover / -pressed / -focus / -disabled / -active。
--comp-tag-bg（default）· --comp-tag-hover-bg · --comp-tag-disabled-bg
4
對齊系統設計決策
shape 永遠引用 sys.shape.sharp（0px），除非是 filter-tab 的唯一例外（sys.shape.accent = 2px）。不引入新的圓角值。motion 統一引用 sys.motion 層。
✓ shape: var(--sys-shape-sharp)   ✗ border-radius: 4px（不允許）
